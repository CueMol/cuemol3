CueMol 3.0.6 (build 577)

The main changes:

- **Choose a molecule's paint colour (CueMol3)**: Paint coloring now lists
  the palette themes (Okabe-Ito, Paul Tol, ColorBrewer, Tableau) with each
  colour by name and a swatch, plus the CueMol2 and CueMol1 (woody) default
  colours.
- **cuetty for Linux clusters**: a portable Linux build of the command-line
  renderer. It can split a movie's frames across cluster jobs.
- **Brighter Fast GI, exact unlit colours (CueMol3)**: Fast GI is brighter by
  default, and backgrounds, lines and labels come out in exactly the colour
  you set.
- **Side / main chain selection of DNA (all)**: `bysidech` now picks up the
  thymine methyl group, `bymainch` the phosphate oxygens, and `bymainch`
  no longer selects water.

---

## Coloring (CueMol3)

- The Coloring menu (the coloring panel's type dropdown and a renderer's
  right-click **Coloring** menu) is reorganized:
  - **Molecule color** is a top-level item: the renderer takes its colours
    from the molecule. This is how ribbon, cartoon and tube renderers start.
  - **Paint coloring** gives the molecule or renderer its own paint table:
    - **CueMol2 default** or **CueMol1 (woody)** colours.
    - A colour from any palette theme, as the main colour of the molecule
      (helix and sheet in that colour, nucleic acid shifted slightly in hue,
      coil pale). Each colour is listed by its name with a swatch.
    - For a renderer, the single-colour presets, now ordered by hue
      (Red, Orange, Yellow, Green, Cyan, Blue, Purple).
  - The automatic "Default" item is gone. A newly loaded molecule is still
    painted automatically, and picking the same theme colour gives the same
    result.
- On macOS, the coloring panel's dropdown opens as a native menu.
- Console / AI tools: `set_renderer_coloring` takes `paintColor` (a theme
  colour such as `okabeito_3`, or `cuemol2` / `cuemol1`), and
  `list_coloring_styles` lists the themes and their colours.

## Display (CueMol3)

- **Fast GI** is brighter by default. GTAO and no-AO are unchanged.
- Backgrounds, lines, labels, edge lines and unlit (`nolighting`) materials
  are drawn in exactly the colour set: a `#FFFFFF` background stays pure white
  in screenshots and PNG export. These no longer cast ambient occlusion.
- The `nolighting` material outputs the given colour (it was about 1.2x too
  bright).
- Direct surfaces (`dsurface`) use the `meshms` algorithm by default, falling
  back to `distfield` where it is not available. Scenes saved without the
  setting load with `meshms`.
- Known limit: half-resolution GTAO still changes slightly around lines and
  unlit surfaces when they are shown or hidden.

## Selection (all)

- On nucleic acids with PDB v3 or mmCIF atom names:
  - `bysidech` selects the thymine methyl group (`C7` and its hydrogens). The
    PDB v2, old PDB and CNS names are also recognized.
  - `bymainch` selects the phosphate oxygens `OP1` / `OP2` / `OP3`.
- `bymainch` and `bysidech` select nothing in residues that have no main /
  side chain definition. `bymainch (*)` used to select water, ions and
  ligands.

## cuetty (command-line renderer)

- A portable Linux build, `cuetty-3.0.6.577-linux-x64.tar.gz`, for headless
  cluster nodes (RHEL 8 class or later, x86-64-v3 CPU).
- Movie rendering with `--movie <dir>/<base>`, writing the same frame names
  as the GUI. Frames can be split across jobs (`--frames A-B`,
  `--shard I/N`), and `--skip-existing` resumes an interrupted run.
  - The output directory must already exist. Create it before submitting an
    array job.
- `--threads` sets the thread count. Without it, cuetty follows
  `SLURM_CPUS_PER_TASK`, then `OMP_NUM_THREADS`.
- A scene whose data cannot be loaded in full (a missing file, or a missing
  or unreadable embedded part) now ends with an error instead of rendering
  without it.

## Builds

- The Windows build installs its compiler from the LLVM project's GitHub
  release, after the Chocolatey feed timed out during the 3.0.5 release build.
